# 通话网络恢复：第一批

日期：2026-09-03。复用 LiveKit SDK 恢复媒体传输，不另外实现 WebRTC 重连算法。本批不宣称弱网音视频质量验收完成。

## App

- 订阅 LiveKit RoomReconnecting / RoomReconnected / RoomDisconnected，区分正在恢复和最终断开；断开后不再显示“通话中”。连接恢复后清除恢复提示，初次连接失败与最终重连失败均可重试。
- 房间被关闭、参与者被移除、同账号另一设备连接导致断开时，显示具体提示，不提供无效的重新连接按钮。
- 展示本地或远端 SDK 连接质量 poor / lost 提示，以及接听后远端未出现/离开的等待提示。这是状态展示，不是对双向 RTP 或听感的证明。
- 挂断和无人接听退出不等待 HTTP 返回；退出页面释放媒体资源，最多等待 8 秒的结束报告在后台执行，失败不阻止本地退出。没有新增持久化离线请求队列；后端媒体核对负责可观察的残留状态兜底。
- 挂断统一调用 end，处理发起人还没收到 accept 信号的竞态。end 对合法参与者重复请求幂等，并使用条件更新避免覆盖其他终态。accept 允许接收方对已接听状态安全重试，重发接受信号；不能绕过参与者权限。
- 通话历史展示 MEDIA_DISCONNECTED 为“连接中断，通话已结束”。

## 服务端

- 既有每 15 秒的通话维护增加 LiveKit 房间成员核对，仅检查 ACCEPTED / CONNECTED。
- 经成功的管理 API 查询确认缺少任一通话参与者，开始 90 秒宽限计时；两人重新出现则清除计时。连续观察到缺席超过宽限期后，条件更新为 ENDED / MEDIA_DISCONNECTED，尝试清理房间并通知双方。
- 房间不存在必须由成功的 listRooms 查询确认；LiveKit 请求超时、鉴权失败等不视为人员缺席，保留通话状态并重置宽限期。管理 API 请求超时设为 5 秒。
- 90 秒从服务端首次观察到缺席计算，并非从设备实际断网瞬间计算；LiveKit 自身离线检测与维护间隔会增加总时间。正常在场但媒体没有实际流动，不会单凭这个检查结束通话。
- 宽限计时在当前 API 进程内存中，重启后重新给予完整宽限期，尚非多副本强一致设计。房间删除/IM 结束通知仍为 best-effort，没有持久化重试队列；LiveKit 管理 API 不可达期间不承诺结束状态及时收敛。
- 未增加数据库字段、REST 路由或 SDK 依赖。当前本地部署使用 docker-compose.yml + docker-compose.call-recovery.yml，API 镜像 chat-api:call-recovery-local。

## 测试与范围

- 后端新增 7 项测试：宽限边界、双方返回、管理 API 故障不误结束、并发终态保护、accept 重试、end 幂等和权限、发起人挂断与接听竞态。连同既有用例共 76 项通过；lint/build 通过。
- Flutter 新增 5 项测试：临时恢复、最终失败、不可重试的终态、挂断不等响应、同步异常不阻止退出。完整 113 项回归测试通过。
- scripts/smoke-call-recovery.mjs 仅允许回环 API 和 av_ 隔离测试账号。刻意不加入媒体房间，验证接听重试、越权拒绝、30 秒仍保留状态、宽限期后清理、终态 Token 拒绝、再次发起不再忙线、挂断幂等。真实执行结果另记 local-phase-one-acceptance.md。

## 仍需完成

1. 正常网络同轮双向音频 RTP / 实际听感及真机视频基线。
2. 已建立通话下的短断网、长断网、丢包、抖动、限速、Wi-Fi/蜂窝切换，以及只断 API / 只断媒体的独立故障测试。
3. 画质/码率上限、音频优先及视频降级策略。当前未改变默认 RoomOptions，不把 adaptiveStream / dynacast 开关等同弱网验收。
4. TURN/TLS 受限网络兜底；本地 LiveKit 仍是开发模式，不能代表公网连接覆盖。
5. API 与 IM 结束通知都失败、应用被系统杀死、多设备竞争等扩展验证及更可靠的结束事件重试。后台通话/系统音频中断不因本批通过而验收完成。
