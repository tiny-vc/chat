# 跨设备状态同步与可靠补偿

## 第一阶段覆盖范围

- 消息与会话历史：继续由 WuKongIM 的 conversation/channel sync 提供，不复制一套消息存储。
- 已读状态：服务端 PostgreSQL 保存每个用户、每个会话的最大已读序号，只允许单调前进。
- 会话偏好：置顶、静音、归档以服务端 `conversation_settings` 为准。
- App 在登录、WuKongIM 完成离线同步、以及从后台回到前台时进行状态对账。
- 同一用户、同一终端类型使用稳定派生的 WuKongIM Token，并注册为 secondary device，允许两台手机同时在线和断线后重新认证。
- WuKongIM CONNECT 包中的 `device_id` 使用 App 的稳定安装 ID，与业务 `device_sessions.device_id` 一一对应，不再另生成一套无法关联的标识。

## 已读可靠补偿

App 在请求服务端之前，先把已读游标写入按“服务器 + 用户”隔离的安全存储队列。队列具有以下性质：

- 同一会话只保留最大序号；旧请求不会覆盖新游标。
- HTTP 超时、断网、Token 刷新、App 被终止时不会丢失。
- 登录、重连同步完成及回到前台时自动重试。
- 服务端使用 `GREATEST` 幂等写入，重复请求不会让游标倒退。
- 服务端返回 WuKongIM 会话同步数据时，会用持久化游标校正已经完全读完的会话未读数，因此另一设备可以收敛到已读状态。

## 暂不纳入第一阶段

- 输入框草稿仍然仅保存在本机，避免引入频繁上传和隐私争议。
- 当前聊天滚动位置、选中的 Tab、音量及摄像头开关属于设备本地状态。
- 不做每次置顶/静音操作的跨设备实时推送；另一设备会在重连或回到前台时自动拉取。
- 端到端逐消息送达确认仍由 WuKongIM SDK 管理；业务服务不重复实现消息 outbox。
- 用户或管理员下线单个设备时，服务端先持久化撤销业务 API 会话，再通过 `connz` 按 `uid + device_id` 找到连接，调用 `conn/kick` 精确断开。实测 `device_quit` 会断开同账号同终端类型的全部连接，因此不用于单设备下线。
- “退出所有设备”、账号停用及管理员封禁会在持久化撤销全部业务会话后，按 `uid` 关闭该用户当前所有 WuKongIM 连接。
- WuKongIM 暂时不可用时，业务会话撤销仍然成功；现有 IM 连接可能保留到网络重连，但随后无法恢复认证。后台异步补偿可在第二阶段加入。
