# 语音消息联调（2026-09-03）

## 播放交互修复

检查本地 just_audio 源码发现，`play()` 返回的 Future 在播放结束/暂停/停止时才完成，并且自然播放结束时 playing 仍可能为 true。

原语音气泡在第一次加载时把 loading 保持到 `await play()` 完成，使整段播放期间点击暂停失效；图标也只根据 playing 判断，结束后仍可能显示暂停。

现加载/定位完成后立即解除忙碌状态，允许播放过程中暂停；播放图标及操作同时考虑 completed，播完可以直接重播。下载地址等待后补充 mounted 检查，暂停异常也统一提示。气泡增加播放/暂停/加载语音提示及文件 ID 对应的控件 key。

## 双端测试

在 `messages_flow_test.dart` 原双端命令增加 `--dart-define=TEST_VOICE=true`，两端使用新的相同 TEST_RUN_ID。不能与媒体、离线群聊、并发连发阶段同时启用。

测试脚本 `voice_checks.dart`：

- A 通过真实聊天页“录制语音”启动原生录音，录制一秒后点“取消”；确认取消反馈，B 确认尚未收到语音。
- A 再次从界面开始录音，约四秒后点“结束并发送”，使用真实上传服务、存储与 IM。
- B 收到 ChatAudioContent，检查时长和非空文件；下载后用原生播放器解码，验证可读时长超过半秒。
- B 在聊天气泡上点击播放、暂停、续播，等待自然结束后再次播放并等待结束；观察控件状态变化，最终本轮仅收到一条语音。
- 本测试不会证明人声内容、音量、清晰度或物理扬声器输出正确；模拟器可能录到静音。真机、Android、权限拒绝、后台录音、听筒/蓝牙及多条语音互斥播放需另行验收。

仅使用专用开发账号和模拟器；麦克风测试应在无敏感谈话的环境运行。模拟器麦克风权限可以通过开发测试配置授予，不修改 macOS 麦克风权限；若宿主系统阻止录音，应由用户授权，不绕过。完成后重新构建并安装普通入口，避免遗留测试参数。
