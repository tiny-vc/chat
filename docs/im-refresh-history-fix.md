# IM 刷新与历史同步修复（2026-09-03）

## 刷新竞态

服务端刷新会更新 WuKongIM 用户令牌。旧连接可能收到 DisconnectPacket；SDK 将其当作退出登录，清空 uid/token 并关闭本地数据库。原客户端在 HTTP 返回后仅对相同 uid 更新凭据，因而存在先收到踢线包、再丢弃新凭据的时序风险。

本次在 SessionManager 增加刷新前同步回调：ImService 先 `disconnect(false)`，保留账号、数据库与监听器，再发出刷新请求。持久化新凭据后更新 SDK 并自动连接。不在 HTTP 刷新拦截器内等待 IM 同步或再次初始化数据库，避免循环等待。普通 App 与双端测试使用同一套回调。

并发刷新仍合并为一个请求；刷新被拒绝或返回空响应时清理会话，不恢复旧连接。该修复不改变后端令牌轮换或其它设备的登录策略，也不声称覆盖退出登录与刷新同时发生的所有边界。

## 历史同步 400

`20260903-refresh-01` 在两端记录了相同失败参数：`channelType=1, startMessageSeq=-1, endMessageSeq=0, limit=50, pullMode=0`。

SDK `db/message.dart` 在本地记录不足一页、oldestMsgSeq 为 0 且 contain 为 false 时计算 `oldestMsgSeq - 1`，产生 -1。后端 DTO 要求游标至少为 0，因而拒绝请求。

应用适配层仅将向旧记录拉取时的起始 -1 转换为协议的最新位置 0，其它分页参数保持不变，不放宽后端验证。请求失败时回调 null（SDK 的失败分支），不再用空成功结果冒充历史结束。
