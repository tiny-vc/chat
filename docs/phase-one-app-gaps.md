## WuKongIM / LiveKit 利用情况

基于现有代码核对，不是对 SDK 所有功能的穷举：

- WuKongIM：Flutter 直接通过 SDK 连接、发送/接收消息和同步历史；后端通过管理 API 管理用户凭据、群订阅、频道策略、黑名单及系统通知。没有在 NestJS 内另建消息投递与排序服务。
- 本批禁言入口调用业务权限接口，后端继续调用 WuKongIM 的频道策略/黑名单接口执行既有规则。App 不靠隐藏发送按钮模拟服务端禁言。
- LiveKit：Flutter 使用 Room、音视频轨道发布/订阅、设备控制及 SDK 连接状态；后端签发限定房间、15 分钟有效期的 Token，并在通话结束清理房间。媒体流不经业务 REST API。
- 业务后端保留账号、好友、群角色、文件权限、来电邀请/拒绝/超时等产品状态，和媒体房间连接分开。这些并不是对消息传输或 WebRTC 的重复实现。
- 当前使用了两者的核心能力，但不应说所有能力已充分验收。LiveKit 同轮双向 RTP 测试仍未通过；真机视频、听感、弱网恢复未完成。CallPage 已显式启用 adaptiveStream、dynacast、720p/24fps、simulcast 和 balanced 降级，并实现音频优先策略；这些配置不能替代真实设备及受限网络验收。
- 文件字节走对象存储，聊天消息携带文件元数据；不把大文件转为 IM 消息体，也不使用 LiveKit 数据通道替代持久聊天。

## 第二批：入群申请、邀请与审批

- 通讯录右上角新增“入群申请与邀请”；可按 UUID 格式群 ID 提交申请及选填说明（最多 500 字符），查看最近 100 条个人记录。

- 已处理和已过期记录不提供操作。提交前再次检查过期时间；服务端仍负责最终权限、容量、过期和并发状态裁决。服务端冲突/操作失败后重新读取记录，加载失败显示重试入口。
- 每次操作需要确认；请求期间禁用重复操作；长内容使用可滚动布局，按钮采用 Wrap 适配大字体。

- 拒绝入群申请或邀请时现已支持填写最多 500 字的选填原因，并沿用既有接口传给对方；群公开搜索不属于当前私有群第一阶段范围。统一待办入口及数量提醒已在后续批次实现。

### 同步修复的接口兼容性问题

listMyJoinRequests 原先选择的嵌套 group 缺少 GroupResponse 必填的 ownerId、memberLimit、muteAll，会造成生成 Dart 客户端的反序列化失败。本轮补齐三项返回字段，保持 OpenAPI 与客户端不变；新增后端测试将 select 字段与 GroupResponse.required 对照验证。

新增客户端请求测试在 Dio 内存拦截器返回真实形状的群摘要，验证个人/群列表解析、申请、邀请、同意、拒绝、撤回的路径、HTTP 方法及请求体，不产生网络请求。
