## 第一批：群角色与禁言

群聊资料页已接入以下已有接口，使用生成的 GroupsApi / DTO，不新增后端协议：

| 操作 | 接口 | App 约束 |
| --- | --- | --- |
| 设置/取消管理员 | PATCH /groups/:id/members/:uid/role | 仅群主，二次确认 |
| 转让群主 | POST /groups/:id/transfer-owner | 仅群主，明确说明原群主变管理员、不能自行撤回 |
| 成员禁言/解禁 | PATCH /groups/:id/members/:uid/mute | 群主可管理非群主成员；管理员只管理普通成员 |
| 全员禁言 | PATCH /groups/:id | 群主/管理员，确认后发送 muteAll |

成员右侧菜单提供入口。禁言时长为 15 分钟、1 小时或 24 小时；返回新群资料后展示禁言截止时间。后端仍是最终权限裁决者，App 隐藏按钮不是安全边界。

请求期间禁用操作；操作后重读群资料与首页数据；群资料刷新失败时保留展示但禁用操作，并提示刷新重试。未做乐观权限更新。

验证：flutter analyze 无问题；79 项 Flutter 测试通过，新增 5 项页面测试和 1 项请求序列化测试。覆盖角色可见性、确认取消、请求期间禁用、转让后失去群主按钮、禁言时长/解禁、刷新失败及重试、六次请求的 method/path/body。

未做真实角色转让、真实群禁言的双端联调；未提交账号凭据或修改真实群数据。既有认证联调权限阻断仍有效。本次并未证明消息服务上的禁言限制已端到端生效。

## WuKongIM / LiveKit 利用情况

基于现有代码核对，不是对 SDK 所有功能的穷举：

- WuKongIM：Flutter 直接通过 SDK 连接、发送/接收消息和同步历史；后端通过管理 API 管理用户凭据、群订阅、频道策略、黑名单及系统通知。没有在 NestJS 内另建消息投递与排序服务。
- 本批禁言入口调用业务权限接口，后端继续调用 WuKongIM 的频道策略/黑名单接口执行既有规则。App 不靠隐藏发送按钮模拟服务端禁言。
- LiveKit：Flutter 使用 Room、音视频轨道发布/订阅、设备控制及 SDK 连接状态；后端签发限定房间、15 分钟有效期的 Token，并在通话结束清理房间。媒体流不经业务 REST API。
- 业务后端保留账号、好友、群角色、文件权限、来电邀请/拒绝/超时等产品状态，和媒体房间连接分开。这些并不是对消息传输或 WebRTC 的重复实现。
- 当前使用了两者的核心能力，但不应说所有能力已充分验收。LiveKit 同轮双向 RTP 测试仍未通过；真机视频、听感、弱网恢复未完成。CallPage 当前采用默认 Room 配置，后续是否显式配置自适应订阅、视频编码/码率等，应根据真实设备测试决定，而不是仅打开开关就算优化完成。
- 文件字节走对象存储，聊天消息携带文件元数据；不把大文件转为 IM 消息体，也不使用 LiveKit 数据通道替代持久聊天。

## 第二批：入群申请、邀请与审批

- 通讯录右上角新增“入群申请与邀请”；可按 UUID 格式群 ID 提交申请及选填说明（最多 500 字符），查看最近 100 条个人记录。
- 群资料页提供复制群 ID；群主/管理员可进入“入群审批”。邀请列表也显示在这里，但管理员不能代替被邀请人接受或拒绝邀请。
- 我的入群申请可撤回；收到的邀请可接受/拒绝；自己发送的邀请可撤回；群管理员可同意/拒绝本群申请。
- 已处理和已过期记录不提供操作。提交前再次检查过期时间；服务端仍负责最终权限、容量、过期和并发状态裁决。服务端冲突/操作失败后重新读取记录，加载失败显示重试入口。
- 每次操作需要确认；请求期间禁用重复操作；长内容使用可滚动布局，按钮采用 Wrap 适配大字体。
- 群资料的“邀请好友入群”改为单次选择一位好友并调用 invitations 接口，等待对方接受，不再直接调用 addMembers。后端原 addMembers 接口保留，没有修改旧客户端契约。
- UI 尚未提供填写拒绝原因（接口仍支持）；没有群公开搜索，也未添加待处理数量角标；不能把这些说成已完成。

### 同步修复的接口兼容性问题

listMyJoinRequests 原先选择的嵌套 group 缺少 GroupResponse 必填的 ownerId、memberLimit、muteAll，会造成生成 Dart 客户端的反序列化失败。本轮补齐三项返回字段，保持 OpenAPI 与客户端不变；新增后端测试将 select 字段与 GroupResponse.required 对照验证。

新增客户端请求测试在 Dio 内存拦截器返回真实形状的群摘要，验证个人/群列表解析、申请、邀请、同意、拒绝、撤回的路径、HTTP 方法及请求体，不产生网络请求。

## 第三批：群头像

- 群资料页使用 AppAvatar，按 avatarFileId 通过受保护下载接口解析地址；无头像或读取失败显示默认群图标。
- 群主/管理员可以上传、更换和确认移除头像；普通成员只查看。使用生成的 GroupsApi 调用 PUT /groups/:id/avatar（fileId）和 DELETE /groups/:id/avatar，不新增后端协议。
- 上传复用 FileTransferService.uploadAvatar：私有 AVATAR 文件先上传并完成，再绑定群；成功后重新读取群资料和首页。选图期间即禁用重复操作，上传显示进度；取消、选图异常、上传/绑定失败均恢复按钮，失败不主动清除旧头像。
- “移除”解除头像绑定、恢复默认头像，不物理删除存储对象，也不删除聊天图片；绑定失败的上传文件沿用现有文件清理策略。本轮没有新增裁剪、压缩或跨设备头像变更推送。
- 新增 5 项替身页面测试，覆盖普通成员权限、管理员上传、取消/选图异常、重复点击、上传及绑定失败重试、移除确认；扩展请求契约测试验证头像接口方法、路径和请求体，全部不访问真实账号。
